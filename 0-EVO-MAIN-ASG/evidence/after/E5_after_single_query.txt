Method: MariaDB general_log captures the SQL each page load actually fires.

Proves: the books.php "All Books" page now issues exactly ONE query
to render the entire table, replacing the previous 2N+1 pattern that
fired 36 queries for 17 active books. The available-copies number
the librarian sees is computed using the SAME formula the E1
borrow_save.php validator uses, so the UI cannot show "1 available"
while the validator rejects the borrow.

POST-E5 query count
======================================================================
Same page, same data, same session.

  SELECT COUNT(*) AS total_queries FROM mysql.general_log WHERE command_type='Query';
  -> 2   (1 page query + 1 'SET GLOBAL general_log OFF' from the test harness)

Only relevant query:
  SELECT b.book_id, b.book_title, b.author, b.book_copies,
         b.book_pub, b.publisher_name, b.isbn, b.copyright_year,
         b.date_added, b.status, c.classname,
         b.book_copies - COALESCE(SUM(CASE WHEN bd.borrow_status='pending' THEN 1 ELSE 0 END), 0) AS available
    FROM book b
    LEFT JOIN category      c  ON c.category_id = b.category_id
    LEFT JOIN borrowdetails bd ON bd.book_id    = b.book_id
   WHERE b.status != 'Archive'
GROUP BY b.book_id, b.book_title, b.author, b.book_copies,
         b.book_pub, b.publisher_name, b.isbn, b.copyright_year,
         b.date_added, b.status, c.classname
ORDER BY b.book_id

Reduction:
  36  -> 1     (page render)
  18x fewer round trips per row (was 2 per row + setup, now amortised
  across one query)
  Per-page improvement: 36 -> 1 = 35 fewer queries per books.php load.

"Single source of truth" check (E1 vs E5 formula parity)
======================================================================
librarian/borrow_save.php (E1 validation, lines 37-43):
  SELECT b.book_id, b.book_copies,
         b.book_copies - COALESCE(SUM(CASE WHEN bd.borrow_status='pending' THEN 1 ELSE 0 END), 0) AS available
    FROM book b
    LEFT JOIN borrowdetails bd ON bd.book_id = b.book_id
   WHERE b.book_id IN (?...)
GROUP BY b.book_id, b.book_copies

librarian/books.php (E5 listing):
  ... b.book_copies - COALESCE(SUM(CASE WHEN bd.borrow_status='pending' THEN 1 ELSE 0 END), 0) AS available
       FROM book b
  LEFT JOIN borrowdetails bd ON bd.book_id = b.book_id ...

Identical predicate (status='pending'), identical arithmetic
(book_copies - COUNT(pending)), identical COALESCE. So a book that
shows up as "0 available" on books.php is guaranteed to be rejected
by borrow_save.php with "Book ID N has no available copies", and
vice versa.
